pi-worklist goal board live reload, run in a real terminal
target commit: 01b0d6143a46215a5bea05528eb491e69b2c62a0
base commit:   2d4e91cdb1a4562ebd23599f5c337695da87fb98

Each run opens `pi-worklist project ui` in a 100x26 tmux pane, then adds a goal
from a separate pi-worklist process and waits up to 15s for the board to show it.

Four `fs.watch` states are exercised. The first is the unmodified host, with no
harness in the picture at all. The other three load a small module hook that
replaces `fs.watch` for the board module only: passing straight through to the
host's watcher, refusing to create one (EMFILE, the exhausted-inotify-instance
failure), and creating one that then fails, which stands in for a watcher that
silently stops delivering events.
